# scripts/phi-allow-list.txt
#
# PHI-scan allow-list: the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. Byte-strict wire formats cannot carry an
# inline `# synthetic: true` header (the header segment must be the first bytes),
# so this allow-list is the synthetic-fixture declaration mechanism: the same
# approach every sibling `@cosyte/*` parser uses.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word, matched case-insensitively
#   DOB <value>           synthetic date of birth (normalize as your detector does)
#   ID <value>            synthetic id matching an SSN / MRN / member-id shape
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#
# The engine's floor consumes EMAILDOMAIN and ID (an email, and a dashed SSN
# checked both as written and with its separators removed). The field-level
# detectors in scripts/phi-detect.ts consume NAME, DOB and ID for HL7 v2, FHIR,
# X12 and C-CDA: a NAME line is one name token, matched upper-cased; a DOB line
# is the date's digits, YYYYMMDD (YYYYMM or YYYY when partial), so one line
# covers 19700101 in HL7 and X12 and 1970-01-01 in FHIR; an ID line clears an
# all-digit identifier or a phone.
#
# 🛑 EVERY DETECTOR YOU ADD MUST CONSULT THIS FILE. `--allow-fixture` is recorded
# and then REFUSED, so it cannot reach a clean run: a detector that checks
# nothing here leaves a hit with no remedy at all, which is how a gate gets
# routed around rather than answered.
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act: never silent.

# --- Reserved / test email domains (RFC 2606 / 6761) ---
EMAILDOMAIN example.com
EMAILDOMAIN example.org
EMAILDOMAIN example.net
EMAILDOMAIN example.test

# --- The vendor's own contact address ---
# `package.json`'s `author` field carries hello@<this domain>, and the scan roots
# are the whole repository, so the sweep reads it on every run. It is the
# publisher's public contact address, not a patient's, and it is present in every
# @cosyte/* manifest. Declared rather than excluding package.json, because the
# manifest is otherwise worth scanning.
EMAILDOMAIN cosyte.com

# --- SSH protocol names ---
# SSH names an extension or algorithm a vendor defines as name@domain (RFC 4251, section 6):
# posix-rename@openssh.com, fsync@openssh.com, hmac-sha1-etm@openssh.com and the like, which the
# SFTP location and its tests use. Protocol identifiers, not anyone's address.
EMAILDOMAIN openssh.com
