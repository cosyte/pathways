An HTTP destination can settle each delivery by an HL7 v2 XML acknowledgement.

- A new key on an `http` destination, `ack: xml`: a 2xx answer's body is read, up to 1 MiB and within the destination's `timeout`, as an HL7 v2 XML acknowledgement, the answer a web service that takes v2 XML sends on the same connection. Its `MSA.1` settles the delivery: `AA` or `CA` is delivered; `AE` or `CE` is retried, coded `ACK_AE` or `ACK_CE`, within the destination's retry settings; `AR` or `CR` fails the delivery for good. That is the other way round from an MLLP destination, following the public description of the exchange this was written for. A status that is not 2xx is read by the status table as before.
- An answer is read in one shape only: exactly one `MSA` in the whole document, a child of its root; exactly one `MSA.1` and at most one `MSA.2`, children of that `MSA`, holding text alone; at most one `MSH`; and a code that is exactly `AA`, `AE`, `AR`, `CA`, `CE` or `CR`, with no whitespace and in upper case. An answer in any other shape, not XML, over 1 MiB or cut short is retried as `ACK_UNREADABLE`, never settled by the first `MSA` or `MSA.1` found.
- The message sent is read once per delivery, before its first POST, whatever its size. It must hold exactly one `MSH`, at any depth, with exactly one `MSH.10` holding text alone; an acknowledgement whose `MSA.2` is not that `MSH.10`, or any answer to XML of another shape, is retried as `ACK_CONTROL_ID_MISMATCH`. A message sent as XML the reader refuses (not well-formed, not UTF-8, or with a document type declaration or an entity anywhere) is not sent, and the delivery fails at once with the reason `SENT_XML_UNREADABLE`. The control ID check is skipped only for a body that is not XML at all, so a pipe-delimited body sent with `ack: xml` is settled by its code alone.
- `ack: xml` needs the destination's format to be `hl7v2` or `text`; with `fhir`, `x12`, `ccda`, `json` or `csv` the channel is refused at load.
- The XML is read with `@cosyte/ccda`'s hardened reader: no document type declaration or entity, at most 32 elements deep and 20,000 nodes. Elements are matched by local name, so the HL7 namespace, a prefix and no namespace read the same. Only `MSA.1`, `MSA.2` and the sent message's `MSH.10` are read; nothing of the answer is logged.
- Without the key, nothing changes. The setting follows the public description of the animal diagnostic lab network's results exchange and has not been tested against the network itself, whose onboarding needs accounts and certificates only a lab holds. No caller needs to change anything.
