The health endpoint serves the engine's metrics at `GET /metrics`, in the OpenMetrics 1.0 text format, for Prometheus or any collector that reads it.

- `/metrics` answers `application/openmetrics-text; version=1.0.0; charset=utf-8`, written by Pathways itself with no client library, behind the health endpoint's bearer token or mutual TLS. It is on by default. Before, `/metrics` answered with the health body, as any path did.
- The families: `pathways_messages_received_total`, `pathways_messages_refused_total`, `pathways_transforms_total`, `pathways_deliveries_total`, `pathways_messages_settled_total` and `pathways_settled_destinations_total` (counters that start at 0 when the engine starts, each with `_created`), `pathways_delivery_duration_seconds` (a histogram of each delivery attempt), and the gauges `pathways_queue_depth`, `pathways_oldest_pending_age_seconds`, `pathways_deliveries_retrying`, `pathways_deliveries_failed` and `pathways_messages_failed` (read from the database, one set of reads serving the scrapes of the next 5 seconds), `pathways_source_up`, `pathways_open_connections`, `pathways_store_up` and `pathways_store_latency_seconds`. The configuration reference lists them as a stable contract: a name is never renamed or reused.
- Labels are only `channel`, `destination` (the destination's `name:`, or its place in `destinations:` from 0 where it has none) and an `outcome` from a fixed list, never a message id, a control id, a patient field, a metadata key, a URL, an error's text or a host. Every label value is escaped, so no channel name can break the text. A destination's store gauges follow its deliveries by its destination key, so they stay with it when the list is reordered.
- A message handed between channels, by a channel destination or `ctx.route`, counts as received once on each channel, and the hand-off as a delivery of the channel it leaves. Each piece of a batch counts as a message. A body a source refused counts in `pathways_messages_refused_total`, as `unreadable` (kept as failed and never transformed, such as a frame with a second message header) or `rejected` (an HTTP source's 400, 413, 415 or 422 before storing), and never as received. The settled counters add one for each `settled` event, and one per destination under the state the event gives it.
- New `metrics` block on `health`: `enabled` (default `true`) and `allowUnauthenticated` (default `false`). A health endpoint that checks no one, `auth: none` and no `tls.ca`, on plaintext or TLS alike, answers `/metrics` with 403 and logs `metrics-refused` at start unless `allowUnauthenticated` is `true`.
- New exports: `METRIC_FAMILIES` (each family's name, type, unit, help and labels), `OPENMETRICS_CONTENT_TYPE`, and the types `MetricFamily`, `MetricType` and `DestinationQueue`. `MessageStore` gains an optional `destinationQueues(channel)`, which the built-in stores have and which gives each queue's `destinationKey`; a custom store without it still runs, and `/metrics` then serves no queue gauges for it.
- `pathways_open_connections` counts the connection an MLLP source with `connect` dialled, as it counts those a listening source accepted; `MllpSource.openConnections` does the same.
- A new how-to, "Collect metrics", covers a Prometheus scrape and alert rules.
- Nothing a caller must change. A monitor that read the health body from `/metrics` must read it from another path, such as `/`.
