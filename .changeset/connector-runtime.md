A schedule per polled source, a deadline on each pass and on every delivery, and a way for a running source to say it lost its connection.

- A `file` or `module` source may set `poll:` beside its kind: an interval such as `30s`, `onStart` for one pass at start, or a mapping with exactly one of `every`, `cron` (five fields, read with `timezone`, `UTC` by default) or `onStart: true`, and a `deadline` (`5m` by default). Without it, a source is polled every `pollInterval`, as before. `poll` on an `http` or `mllp` source, `timezone` without `cron`, a cron expression that is not five fields, or a time zone Node does not know is refused, naming the file and key. Cron expressions are read by croner, a new dependency (MIT, no dependencies of its own).
- Each source's pass runs beside the engine loop, so a source that hangs holds up no other channel. A pass never overlaps itself: one that comes due while the last `poll` call has not returned is skipped and logged as `poll-overlap`. A pass past its deadline is cut off and logged as `poll-deadline`: the signal handed to `poll` aborts, and each later `sink.receive` of that pass rejects with the code `POLL_DEADLINE` before it stores anything, so the source keeps the message. A pass missed while the engine was down, or while the last one ran, is not made up. When `pathways start` stops, a pass under way finishes storing what it is storing and takes nothing more in, its `poll` call is waited for up to its deadline, and what the sources took in goes on through the transform and delivery before it exits, as before. `pathways start --once` polls every source once, whatever its `poll`.
- Every delivery attempt (connecting, sending and the receiver's confirmation) runs under a deadline: an HTTP destination's `timeout` plus a second, twice an MLLP destination's `ackTimeout` plus a second, and a `file` or `module` destination's new `timeout:` key, `30s` by default. At the deadline the destination's `signal` aborts and the attempt is retried as any other failure, with the code `DELIVERY_TIMEOUT`. A custom destination that took longer than 30 seconds before now needs `timeout:` set in its block. The liveness bound counts each destination's deadline, so with the defaults a project with file or module destinations has a bound 25 seconds longer than before.
- API additions: `MessageSink` gains the optional `sourceDown(code)` and `sourceUp()`, which the engine's sink always has. `sourceDown` marks the channel's source `down` on the health endpoint (503) and readiness, logs `source-lost`, sends the hooks `source-down` with `name: "SourceDown"`, and returns how long to wait before reconnecting (1 second, doubling to 5 minutes); `sourceUp` logs `source-regained` and sends `source-up`. A code that is not letters, digits and `_.:-` (at most 64) is kept as `UNSPECIFIED`, so no error text reaches a log. `SourceConnector.poll` takes an optional second argument, the pass's `signal`. Code written against these types keeps compiling unchanged.
- Each output's `messageId` and `seq` stay the same on every attempt and resend; the delivery docs now say how a receiver can use the pair to drop a copy.
