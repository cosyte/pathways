One engine per database, enforced: `pathways start` now takes an engine lease before it opens a source, and every write that records the engine's work is fenced by the lease's epoch. Before, a second engine on the same database ran beside the first, and both could send the same delivery.

- The lease is a row in a new `leases` table: the holder's node id and host, since when, an epoch that rises on every acquisition, and an expiry judged by the database's clock in the same statement that takes or renews it. Migration `0006-leases` only adds the table, so it is safe while deliveries are in flight; it has no rollback step, and dropping the table with every engine stopped undoes it.
- A second `pathways start` on the same database exits 1 and names the holder (node, host, since, epoch, time left), never a URL. The holder renews every third of `lease.ttl` (15s by default, a new `lease` block in `pathways.yaml`). A renewal that is refused, fails, or comes later than the lease lasts by the holder's monotonic clock, or a fenced write that changes nothing, stops all sending and taking in at once, logs `lease-lost` and exits 1. A clean stop frees the lease; a killed engine's lease is taken by the next start after the time to live.
- `pathways start --standby` (or `lease: { standby: true }`) waits on a database server without a lease, a listener, a folder or a body read, answers health with 503 `standby`, and takes over within the time to live plus one renewal interval plus its start. It is refused on SQLite.
- New commands: `pathways lease status` prints the holder; `pathways lease release --force` frees the lease of an engine whose host is gone, and writes a `lease-release` entry to the audit log. The operator commands run beside a held lease as before.
- API addition for custom store implementers: `MessageStore` gains the optional `acquireLease`, `renewLease`, `releaseLease` and `leaseHolder`, and `completeTransform`, `failTransform`, `markSending`, `markDelivered`, `scheduleRetry` and `failDelivery` take an optional last `epoch`: given one, the write changes its row only while the `engine` lease carries that epoch, and otherwise rejects with `LeaseLostError`. A custom store without them needs no change: it runs one engine, unfenced, with a `lease-unsupported` warning at start, and cannot run a standby. New exports: `ENGINE_LEASE`, `LeaseLostError`, and the `LeaseClaim`, `LeaseClaimant`, `LeaseHolder` and `LeaseStore` types. `HealthReport.status` gains `standby`, and the audit actions gain `lease-release`.
- Not covered: the send itself cannot be fenced, so an engine paused after a send and before recording it can mean that one delivery is sent once more, flagged as a possible duplicate, which at-least-once delivery allows.
